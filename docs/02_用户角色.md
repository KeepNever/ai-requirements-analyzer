## 1. 角色总览

| 编号 | 角色 | 核心动作 | 使用频次（预估） | 权限级别 |
|---|---|---|---|---|
| R1 | 销售 | 上传客户材料、查看追问建议 | 高（每次客户沟通后） | 提交 + 查看 + 追问管理 |
| R2 | 产品经理 | 查看/修正 AI 分析结果、确认需求 | 高（每批新材料到达后） | 查看 + 修正 + 确认（最高权限） |
| R3 | 售前/解决方案 | 查看需求-能力匹配结果 | 中（需要评估时） | 查看 + 补充匹配意见 |

**角色关系：** 销售供给信息 → 产品经理消费并修正分析结果 → 售前消费匹配结果。信息单向流动，修正权限集中在产品经理，避免多角色并发修改的复杂度。

------

## 2. 角色详述

### 2.1 R1 销售

| 问题 | 回答 |
|---|---|
| 谁 | B端 SaaS 一线销售，同时跟进多个客户，不是分析师，不想做任何"整理"工作 |
| 什么情况下使用 | 每次客户访谈、电话、微信沟通结束后，把原始记录（录音转写、聊天导出、随手笔记）上传系统 |
| 使用前遇到什么问题 | 不知道产品经理需要哪些信息，凭感觉转述经常漏关键点；被产品经理反复追问细节，来回传话；整理纪要占用卖货时间 |
| 希望得到什么结果 | 原始材料丢进去就完成信息传递；系统明确告诉他下一轮见客户该问什么（追问建议），让下一次沟通更有底气 |

**角色动机一句话：用最少的额外劳动完成信息上交，并顺手拿到下次沟通的弹药。**

### 2.2 R2 产品经理

| 问题 | 回答 |
|---|---|
| 谁 | B端 SaaS 产品经理，负责判断客户需求做不做、排优先级，是 AI 分析结果的主要消费者和最终把关人 |
| 什么情况下使用 | 销售提交新材料后收到通知；规划版本、评审需求前回看历史分析 |
| 使用前遇到什么问题 | 人工通读原始材料耗时；判断依赖个人经验，说不清依据；销售转述信息不全，只能反复问；需求优先级争论没有统一标尺 |
| 希望得到什么结果 | 拿到结构化分析：背景、目标、痛点、显性/潜在需求、优先级建议（含依据）、信息缺口、待确认问题清单；可快速修正 AI 判断并留下记录；把节省的时间用在真判断上 |

**角色动机一句话：跳过通读和整理，直接进入判断环节，且判断依据可追溯。**

### 2.3 R3 售前/解决方案人员

| 问题 | 回答 |
|---|---|
| 谁 | 售前或解决方案顾问，负责向客户证明产品能力覆盖其需求，熟悉产品功能边界 |
| 什么情况下使用 | 收到分析报告后评估能力匹配部分；POC 或方案编写前查阅 |
| 使用前遇到什么问题 | 逐条对照客户需求和产品功能靠记忆，容易漏；产品能力边界（支持/不支持/需定制）分散在文档里；客户问到不支持的功能时才发现踩坑 |
| 希望得到什么结果 | 一眼看到需求与产品能力的匹配程度和能力缺口；对不支持的项，明确知道是"确认需求后可定制"还是"硬缺口" |

**角色动机一句话：不靠脑内检索产品功能，快速判断能不能接、怎么接。**

## 3. 动机重叠检查（完成标准）

| 检查项 | R1 销售 | R2 产品 | R3 售前 | 结论 |
|---|---|---|---|---|
| 核心动作 | 提交材料+拿追问 | 判断需求+修正 AI | 评估能力匹配 | ✅ 互不相同 |
| 消费的分析部分 | 追问建议 | 全部报告 | 产品匹配部分 | ✅ 各取所需 |
| 是否修改 AI 结果 | 否 | 是（唯一） | 否（仅补充意见） | ✅ 无冲突 |

**三角色动机互不重叠，通过检查。**

## 4. V1 不做的角色（明确排除）

| 排除角色 | 排除原因 |
|---|---|
| 管理员/超级管理员 | V1 无多租户和权限体系需求 |
| 企业负责人 | 不直接操作系统，消费的是产品经理的二次输出 |
| 客户（外部） | 系统仅内部使用，客户不接触 |
| 数据分析师 | V1 场景中无此角色 |

------

## 5. 关键交互约束（从角色分析导出，供后续设计引用）

1. **销售上传要零门槛**：支持粘贴文本和上传文件，不强制填结构化表单——否则 R1 不会用。
2. **AI 判断必须可修正且修正留痕**：修正权限只在 R2，记录 AI 判断、人工判断、修改原因三项——差异化点 4 的数据来源。
3. **报告按角色分层呈现**：R2 看全量，R3 默认聚焦匹配部分，R1 只看追问建议——一个报告，三种视图。
4. **信息缺口和追问自动流向 R1**：产品经理不用手动转达，系统直接把待确认问题推给对应销售。
