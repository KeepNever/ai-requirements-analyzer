## AI客户需求分析助手｜竞品分析文档（v1.0）

------

## 1. 对手零：现有的人工流程（最重要的竞争对手）

| 维度 | 现状 |
|---|---|
| 构成 | 人工 + 即时通讯 + Excel/CRM + 会议纪要 |
| 耗时 | 单次客户访谈后整理 30~60 分钟（03 号文档 P1） |
| 错误率 | 需求理解偏差导致的返工占项目总成本 15%~20%（Standish Group） |
| 用户换用阻力 | 灵活、零学习成本、已在组织习惯里 |

**含义：本产品不需要打败另一个 AI，但必须在这条流程最痛的环节上显著更快、更完整，否则没人换。** 这是所有竞品分析里最硬的基准线。

## 2. A类：客户会议总结工具（记录层）

### 2.1 飞书妙记（字节）

| 维度 | 内容 |
|---|---|
| 输入 | 飞书视频会议（原生）、上传音视频 |
| 输出 | 转写文本、结构化纪要、待办提取、知识问答 |
| AI 能力 | ASR 中文准确率约 96%，智能纪要、发言人识别 |
| 解决的问题 | 会后整理时间从 2 小时压到 10 分钟 |
| 停留在哪一步 | 总结与待办层。没有需求结构化，没有显性/潜在区分，不判断优先级，不衔接产品决策 |

### 2.2 通义听悟（阿里）

| 维度 | 内容 |
|---|---|
| 输入 | 线上会议、线下录音、采访、网课 |
| 输出 | 实时转写、章节速览、发言总结、PPT 提取 |
| AI 能力 | 中文准确率 96.2%（2026 公测数据，行业头部），覆盖 16 种语言 |
| 解决的问题 | 通用音频转结构化笔记 |
| 停留在哪一步 | 同上——总结层。通用笔记定位，不深入任何业务判断 |

### A类小结

中文转写和纪要已经被国产工具卷成**准免费 commodity**（免费额度 300 分钟/月级别，准确率 95%+）。这层市场已解决，且它们是我们的**上游供给**而非对手——妙记的转写结果正好可以作为本产品的输入材料。

## 3. B类：AI销售助手（交易信号层）

### 3.1 Gong

| 维度 | 内容 |
|---|---|
| 输入 | 全量销售通话录音、邮件、会议、CRM 活动 |
| 输出 | 通话分析、交易风险预警、教练评分卡、AI 交易简报、预测信号 |
| AI 能力 | Conversation Intelligence 深度最高：话题追踪、风险信号识别（关键人沉默、单线联系人、竞品提及）、2026 年已推进到 Agentic 执行（Custom Agents 自动生成管线评审摘要） |
| 解决的问题 | 销售管理者看不清"对话里发生了什么"：预测、辅导、风险 |
| 停留在哪一步 | **分析的是交易信号，不是需求结构**。产出面向销售经理的 coaching 和 forecast，不面向产品经理的需求判断；无显性/潜在区分，无可解释优先级，无产品能力匹配 |
| 价格 | 约 $100~150/人/月 + 平台费，50 人团队年费约 $13 万，纯企业级 |

### 3.2 Chorus by ZoomInfo

| 维度 | 内容 |
|---|---|
| 输入 | 通话录音 + ZoomInfo 100M+ B2B 联系人库实时富化 |
| 输出 | 实时买方信号、竞品提及追踪、Deal Central 交易风险聚合 |
| AI 能力 | 通话中实时拉出对方角色、融资、技术栈、购买信号 |
| 解决的问题 | 通话时销售不了解对方；交易风险后知后觉 |
| 停留在哪一步 | 与 Gong 同层——交易情报。绑定 ZoomInfo 生态，同样不服务产品经理的需求分析场景 |

### B类小结

B类解决了"交易信号"：这单会不会成、哪里有风险。但它**往上没有走**——把客户说的话转化为结构化需求、判断需求真伪和优先级，这一步在 B类产品里仍然由产品经理在 Gong 之外用 Excel 完成。且价格把中小团队完全挡在门外。

## 4. C类：AI 需求分析与 PRD 工具（文档生成层）

### 4.1 ChatPRD

| 维度 | 内容 |
|---|---|
| 输入 | 用户手写的想法、描述（**需要用户自己组织好上下文**） |
| 输出 | 结构化 PRD、用户故事、验收标准、评审问题 |
| AI 能力 | AI 原生（非旧产品加挂），PRD 结构理解深，还有文档批评功能；10 万+ PM 用户 |
| 解决的问题 | PM 写文档的时间砍半 |
| 停留在哪一步 | **文档写作层**。官方弱点自认：无会议转写、无上下文聚合、"你得先知道自己要什么"。输入侧的非结构化客户信息怎么来，它不管 |
| 价格 | 免费起，Pro $15/月——个人友好 |

### 4.2 Productboard AI

| 维度 | 内容 |
|---|---|
| 输入 | 客户反馈聚合（工单、销售通话记录、访谈）、产品战略 |
| 输出 | 反馈自动分类、趋势识别、优先级建议、路线图 |
| AI 能力 | 反馈规模化分类和机会识别，宣称规划提速 6 倍 |
| 解决的问题 | 客户声音太多，PM 归不过来 |
| 停留在哪一步 | **需求管理层**，最接近我们，但有三个缺口：① 绑定自家平台，AI 按 credit 计费昂贵；② 反馈来源是已结构化的渠道工单为主，不消化原始访谈/聊天记录这种最脏的材料；③ 无显性/潜在区分、无可解释评分依据、无产品能力匹配、无人工修正留痕设计 |
| 价格 | $19~59/制造者/月，AI 另按 credit 计费 |

### 4.3 补充观察：Telos（上下文聚合新玩家）

输入 Slack 对话 + 会议转写 + GitHub 代码库，聚合后生成 PRD 和 Jira 工单——**路线最接近本项目**（先聚合上下文再产出），验证了这个方向被市场认可。但它面向"PM 写文档"场景，不做销售-售前-产品的协作流程，无需求判断框架，$95/月起步。新产品，模板和成熟度不足。

### C类小结

C类解决了"文档生成"：帮 PM 把已经想清楚的东西写出来。**但"从客户原始话术到产品判断"之间的那一层——理解、区分、评分、匹配——是全场空白。**

## 5. 四个差异化点对标：市场覆盖矩阵

| 差异化能力 | A类纪要工具 | B类销售助手 | C类需求/PRD工具 | 本产品 |
|---|---|---|---|---|
| 显性/潜在需求强制分离 + 原文依据 | 无 | 无 | 无 | ✅ 核心设计 |
| 可解释的优先级评分模型（权重+依据留痕） | 无 | 有交易风险分（黑箱、面向成交不面向需求） | Productboard 有优先级建议（绑定平台、不可解释） | ✅ 核心设计 |
| 产品能力匹配（需求 × 能力边界） | 无 | 无 | 无（Telos 接代码库但是为写文档） | ✅ 核心设计 |
| 人工修正留痕 → 评测迭代闭环 | 无 | 无（correction 不回流） | 无 | ✅ 核心设计 |
| 消化最脏的原始材料（访谈/聊天记录） | ✅（转写） | ✅（录音） | ❌（要干净输入） | ✅ |
| 服务角色 | 个人 | 销售管理者 | PM 个人 | **销售-售前-产品协作流** |

**矩阵读法：没有任何一个现有产品同时具备右侧四个勾。这就是切入口。**

## 6. 三问收口（本分析的最终产出）

**市场已经解决了什么？**

记录与转写（A类，已卷成免费 commodity）、交易风险信号（B类，企业级付费、面向销售管理）、PRD 文档生成（C类，个人友好）。三层各自成熟。

**还没有很好解决什么？**

客户原始非结构化信息 → 结构化需求**判断**这一层：没有产品做显性/潜在需求强制分离，没有可解释的需求优先级评分，没有面向需求决策的产品能力匹配，没有人工修正留痕回流。同时 B类太贵服务不了产品经理视角，C类要求干净输入服务不了最脏的一手材料，且没有任何产品以"销售-售前-产品协作流"为单位设计。

**本产品切入哪里？**

在免费纪要工具（供给转写材料）和企业级交易情报（太贵且不对焦）之间的空白带，做轻量的**需求判断层**：消化原始材料，输出带依据的结构化需求、可解释优先级、能力匹配和追问清单，直接衔接需求池。上游可以白嫖 A 类的转写产物，下游补 C 类工具最缺的判断依据——不抢任何一层的现有市场，只做断层。
