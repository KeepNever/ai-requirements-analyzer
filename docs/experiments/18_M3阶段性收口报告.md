## 三、Badcase（自动探针 + 归因）

- **BC-06 ×2（hold_02 EN4↔EN6、hold_03 EN5↔EN5）**：证据不足时 AI 以「不支持/部分匹配」强行归类而非「待确认」。与 dev_07 私有化「过度谨慎」同族——**待确认纪律的双向偏差**（该待确认时武断归类 + 该匹配时过度谨慎），列为 M4 首选靶点。
- ⑦ hold_02 0.5 偏低：引用覆盖不全（三系统总览类需求引用打包），与 BC-COV-variant 同族，M4 候选。

## 四、M3 全程叙事（面试素材）

1. **先建尺子**：GT 先于 Prompt 存在，双人评分（一致率 ③97.3%/④100%）；
2. **三轮治理一条 Badcase**：BC-08 信号传导→作用域副作用→urgency 边界，⑤ 首次超基线；
3. **验证集防过拟合**：曦复核抓出起草串线与证据不一致（同源偏见的实证价值）；
4. **评测器自纠**：拆分感知配对修复 GT 打包宽的误杀（④「评测定义问题」归因纪律的实践）；
5. **未见案例验证**：去名词化后 hold 大屏第四案例保持正确、隐性关键需求零遗漏——**五项可比指标（①②⑤⑥⑦）在从未见过的案例上不低于开发集水平**（③ 无对照值不计入；样本 3，系阶段性证据而非普遍性证明）。

## 五、M4 首要优化点（曦裁定）：F7 判断边界统一规则

不逐条修错误，把 BC-06 双违规、dev_07 过度谨慎、dev_06/07 看板保守降档统一收敛为 **F7 能力匹配的三分判断边界**：

1. **有证据证明核心功能覆盖 → 匹配**：不得仅因「需要系统集成/定制对接」降为部分匹配（落地风险写进备注，不改变结论）；
2. **缺少关键证据、无法判断 → 待确认**：不得武断判定「不支持」或「部分匹配」（hold_02 客流预测、hold_03 广告双源两案）；
3. **能力清单明确不具备核心功能 → 才有依据判不支持**。

预期同时治理「过度谨慎」与「证据不足仍强行归类」两类错误。回归测试集：现有 Badcase（hold_02 EN4、hold_03 EN5、dev_07 EN3/EN5、dev_06 EN1）。
