## 一、规则文本（曦微调后批准）

> **归因直接性**：区分**业务问题的总损失**与**该需求能直接影响的后果**——材料中的损失或收益，只有在「该需求不满足会直接造成或加剧该损失」的因果链清晰时，才可计入影响评级；多因素共同作用、该需求仅能部分缓解损失时，不将业务总损失全部计入影响评分，而应依据该需求能够直接影响的后果及其证据定档；若材料无法明确区分可归因部分，不得仅凭损失总额直接给出 5 分，并须在评分理由中说明依据。

## 三、失败归因：条款为何没咬住 final_01 EN2

run2 评分理由原文：**「预警直接作用于该损耗的削减，因果链清晰（提前提醒打折清货直接减少报废），属直接服务核心业务目标的量化收益，定 5 分」**。

模型把「该需求的目标就是止损」等同于「不满足该需求 → 损失发生 = 直接因果」，完全绕过了归因直接性条款——因为条款的判定键（因果链是否清晰）本身由模型裁量，而模型对这条链的裁量结论就是「清晰」。GT 口径（损失由订货经验与促销策略多因素造成、预警是缓解工具之一）与模型口径（需求与损失目标一致即直接）是**语义层面的因果观分歧**，一轮规则文本无法消除：条款说「部分缓解不计总损失」，模型回答「这不是部分缓解，是直接削减」。

## 四、判定与建议

**按验收标准：主目标未达成 + 修复 0 + 可重复新偏差 3 + ⑤ 两集走低 → R2-a 未通过，v1.9 不建议保留。**

连续两轮（M4-R1 档位校准、M4-R2-a 归因直接性）Prompt 规则均未咬住 ⑤ 跳档，且都伴随新偏差。证据指向一个结论：**「总损失 vs 可归因后果」的因果语义分歧不是 Prompt 规则层可靠解决的问题**——规则写得越细，模型越倾向在理由里复述规则后按原直觉打分。

三个选项供拍板：
- **A（推荐）回滚 v1.7.1，⑤ 跳档挂账**：连续两轮实验留档本身就是作品集的高质量证据链（发现问题 → 假设 → 实验 → 诚实记录未通过）；后续若重启此线，优先考虑评测侧而非 Prompt 侧
- **B 第三轮更操作化的定义**（如「需求缺失时损失是否必然发生、客户是否有其他可控手段」）：连续两轮未咬住，边际成功率低，且每轮 0.2 元 + 双轮纪律的验证成本在累积
- **C 接受 ⑤ 现状进作品集叙事**：0.397 的弱点 + 两轮实验记录 + 口径裁定成文，作为「评测驱动迭代」完整案例的一部分

**附带发现**：双轮验收纪律有效暴露了单轮不可见的问题——两轮间 ⑤ 聚合差最大 0.15（DEV），确认了 R1 报告的噪声警告；后续任何单轮对比结论都不可信。
