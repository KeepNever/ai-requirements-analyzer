# 07 · 外部材料分析与借鉴方案（豆包清洗 / Memory-Palace-OS / meetily）

> 三份外部材料的分析结论与本项目借鉴方案。完整分析细节见各分析过程，本文档为决策摘要。



---

## 一、三份材料一句话定性

| 材料                     | 是什么                                               | 对本项目的一句话价值                                       |
| ---------------------- | ------------------------------------------------- | ------------------------------------------------ |
| 豆包工作数据清洗（3 篇）          | 部门级**结构化表格**数据清洗方法论（守恒校验/死信表/规则样例门禁/决策台账）         | 工程纪律思想可移植，但技术路线不适用（它自己声明不覆盖非结构化文本）               |
| Memory-Palace-OS（35 篇） | 企业现场运营的「事件+AI建议+人工决定+知识沉淀」大产品设计规格                 | **AI 输出可追责性设计到极致**——证据链思想值得取，组织协作外壳（多角色/租户/审批）不取 |
| meetily（开源项目）          | 隐私优先 AI 会议助手（Rust+Tauri，本地 whisper 转写+LLM 总结，MIT） | 「会议→纪要」成熟开源实现，转写产物可直接接入本项目管线                     |

## 二、会议纪要方向结论（曦的想法可行性）

**可行，且路线清晰**：

1. **最低成本路径（推荐先做）**：meetily 导出的纪要文本（带时间戳分段）直接作为本项目清洗器的输入——转写产物就是「每段一行」的格式，天然匹配。先人工导出验证下游分析链路，零开发。
2. **进阶路径**：自建转写管线 `faster-whisper + silero-vad + ffmpeg`（Python，1-2 周含中文调优），支持传音频/视频文件（meetily 的 VAD 参数与模型选型经验直接抄：VAD 前置省 70% 算力、批量模式 2000ms redemption 防句子碎裂、中文场景 medium/large-v3 + int8 量化）。
3. **社区版限制（要知道的坑）**：meetily 社区版无说话人分离（多人会议「谁说了什么」缺失，影响需求归属）、无会议软件自动接入（PRO 付费）、纯桌面应用无 API。
4. **战略定位**：meetily 管采集（会议→纪要），本项目管分析（纪要→需求）——分工清晰，接口就是一个 md/json 文件。

## 三、跨材料借鉴清单（按优先级）

### 第三梯队（治理升级，远期）

- 决策台账（被否决方案+触发条件）与 P-/N- 推演记录（豆包）
- PII 密级分级 L1-L4（差异化管理，评测样例同密级）（豆包）

## 四、明确不借鉴的

- 豆包：LLM 只做边缘的分工红线（非结构化场景 LLM 是主场）、遏增量（对话源头不可控）、字段级指标（文本无对应物）
- MP-OS：多角色权限/租户/事件七态/异步编排/渠道接入（组织协作外壳，个人项目纯负担）
- meetily Rust 代码移植（Python 用 faster-whisper 同级实现）、社区版自动接入会议软件（PRO 能力）

## 五、与现有路线的关系

- 登录+部署（第一梯队 SaaS 化）优先级不变，仍是下一轮候选
- 会议纪要方向与 SaaS 化不冲突：先文件导入验证（零开发），转写管线在登录/部署之后排期
- 本清单各项与 97 测试、97 项既有测试无冲突，均为增量
