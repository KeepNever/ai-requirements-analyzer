# 06 · 面试物料包：AI 客户材料分析工作台

> 用途：面试讲述、追问应答、现场演示的统一底稿。所有数据来自真实工程记录（80 提交 / 10 tag / 97 测试 / 17 篇实验文档），无编造成分。

## 一、简历项目描述（可直接贴）

**AI 客户材料分析工作台**（个人项目，独立完成）

面向 B 端售前与客户成功场景的 LLM 应用：将会议转写、微信记录等非结构化材料转化为结构化需求分析，支持引用可追溯的多轮问答、历史版本管理与多场景扩展。

- 建立**评测驱动的迭代体系**：17 个双人标注案例分四层数据集（开发/冻结/正式验证/盲测），六项量化指标（提取 F1、关键遗漏率、引用错位、优先级一致率等），两轮 Prompt 优化实验未通过即回滚留档，杜绝「调参过拟合」；
- 设计**证据可追溯架构**：原文/脱敏双轨存储、P-D 段落映射、EVD-01 引用真实性校验（模型只能引用检索提供的真实段落，无效引用剔除降级），回答每条结论可回链原文；
- 实现**可插拔多场景引擎**：售前需求分析与学员服务诊断共享清洗、引用、导出底座，场景层 Prompt 独立隔离，97 项自动化测试保证场景切换零退化；
- 全程版本化管理（80 commits、10 个里程碑 tag），Word 报告导出支持历史运行绑定与隐私脱敏。

## 二、项目讲解稿

### 3 分钟电梯版

> 这个项目解决一个真实痛点：售前和客户成功同学每天泡在会议转写和微信记录里，客户说了什么需求、有什么风险，靠人肉翻聊天记录。
>
> 我分两期做的。**第一期只回答一个问题：这个 LLM 应用到底可不可靠。**我建了 17 个案例的评测集，每个案例双人标注标准答案，分开发、冻结、正式验证、盲测四层——防止在练习题上调好、考试题露馅。用六个量化指标驱动迭代：提取 F1、关键遗漏率、引用错位、优先级一致率这些。这期间做了两轮优化实验，都没通过验收，我直接回滚留档——比如优先级跳档实验，Prompt 改了之后目标案例零改善还引入 4 处新偏差，判定不通过。这两次失败后来成了 V2 的方向依据：指标上不去的地方，先挂账，用产品能力补。
>
> **第二期把它做成能用的工作台**。核心是三件事：一是版本化存储，原文和脱敏文本双轨，每份材料、每次分析都有版本可回溯；二是引用式问答，模型只能引用检索提供的真实段落编号，引用不存在就剔除降级——用户看到的每条结论都能点回原文；三是评测器本身也进入持续回归，97 项自动化测试保证每次改动不退化。
>
> 最近又做了场景化扩展：同一套底座，换一个场景 Prompt 就能做学员服务诊断——这是我自己做学员服务时的真实需求。场景之间 Prompt 和输出结构完全隔离，用原有案例做回归验证零退化。

### 深挖版要点（面试官追问时展开）

**「评测体系怎么建的？」**——17 案例双人标注；四层数据集防过拟合；六指标各有口径文档；GT 有裁定日志（有争议的标注写裁定理由存档）；评测器本身也有单测。

**「Prompt 怎么迭代的？」**——单变量原则：每轮只改一处（维度独立性 → 反例去名词化 → urgency 量化口径 → F7 边界规则），每轮全量回归 17 案例。两轮失败实验（优先级跳档、归因直接性）都写了完整归因报告后回滚。结论：⑤优先级一致率是模型能力边界，不是 Prompt 能解决的，转产品方案补。

**「失败实验为什么值得讲？」**——因为留档了。docs/experiments 下 17 篇实验文档，包括两次失败的完整归因。大多数人的 LLM 项目只有成功案例，无法证明判断力；失败留档 + 回滚决策恰恰是工程判断力的证据。

**「引用怎么防编造？」**——三层：① Prompt 层要求只引用提供的段落编号；② EVD-01 校验层：模型输出的编号不在检索提供的集合内就剔除，全部无效则答案降级为「证据不足」；③ 测试层：专项测试验证编造被拦截。基线数据：引用有效率 1.0（零漏网）。

**「为什么不用向量检索？」**——材料规模小（单案例几十段），词面检索 + 小材料全量供给策略已让证据可达性达到 1.0；向量检索是组件化设计中的可替换项，等材料规模上百段再上，属于成本收益判断而非能力缺失。

**「多场景怎么隔离？」**——场景层只换 Prompt 和输出结构，底座（清洗、引用、导出、评测）共享。meta 带 scene 标识，导出按 scene 分支到不同报告模板。隔离用测试保证：售前 meta 无场景字段、服务分支不误触售前章节、Prompt 版本号互不污染。

## 三、追问应答卡（高频硬问题速查）

| 追问 | 应答要点 |
|---|---|
| 你的项目和套壳产品区别在哪？ | 套壳没有评测体系和证据链。我有 17 案例量化基线、EVD 引用校验、失败实验留档——能证明可靠，而不是演示一个挑好的例子 |
| 数据准确率多少？ | 分层报：引用有效率 1.0、证据可达性 1.0、拒答判断 0.895（DEV 集）、提取 F1 0.7~0.83；弱项主动讲：优先级一致率 0.397 是模型能力边界，已挂账转产品方案 |
| 遇到的最大困难？ | 两个：一是词汇鸿沟（用户问「需求」材料写「报表汇总」，字面检索零命中）——用小材料全量供给策略解决，证据可达性 0.889→1.0；二是多轮假对话——会话留痕了但每轮只发当前问题，重构成历史轮次进 LLM 上下文 |
| 安全隐私怎么处理？ | 原文/脱敏双轨：raw_text 只在后端审计，LLM 输入和前端展示全部用 clean_text（PII 前置脱敏）；Word 导出只写脱敏文本，脱敏失败时失败关闭（输出占位不输出原文），有专项测试 |
| 如果重做会改什么？ | 更早上版本化存储——V1 的 output/ 目录会被重跑覆盖，吃过错之后才设计的 V2 存储层；向量检索会更早做组件化预留 |
| 团队协作怎么做的？ | 个人项目但按团队纪律执行：每次改动 97 测试全绿才合入、里程碑打 tag、失败实验留档、四轮外部审查（每轮 6+ 问题全部闭环） |

## 四、现场演示动线（5 分钟）

| 步骤 | 操作 | 讲解词要点 |
|---|---|---|
| 1 | 工作台粘贴一段脏对话 → 清洗预览 | 「不用手动编号，直接粘贴，清洗器自动兜底；PII 前置脱敏」 |

| 6 | 资料库 → 导出 Word | 「正式交付物，历史运行绑定，脱敏导出」 |
