5. **评测 Dashboard**（`/dashboard`）：六指标 × 四数据集，评测驱动迭代的证据面板

## 三、关键技术点

### 1. 清洗器 v3：真实使用零门槛
- 用户直接粘贴原始对话（无任何编号）时，按非空行自动编号（纯时间戳行过滤、说话人前缀保留）——**真人零门槛**，此前「必须手动加 P 编号」的门槛被移除（曦实测反馈驱动）
- PII 双轨：raw_text（后端审计）/ clean_text（进 LLM 与前端展示），脱敏前置

### 2. 检索：段落级关键词匹配 + 三层回落
- n-gram 命中计分，零向量依赖（材料规模 ≤40 段时够用且可控）
- 停用词过滤（问句功能词不稀释有效关键词）
- **零命中三层回落**：会话历史引用段落 → 小材料全量段落（词汇鸿沟兜底）→ 大材料才判证据不足

### 3. 引用式问答：证据可靠性闭环
- **EVD-01 引用校验**：模型只能引用检索提供的真实段落编号，无效引用剔除并警示，全部无效则降级「证据不足」——不编造
- **真多轮**：历史轮次（最近 5 轮）作为上下文进入 LLM 消息，追问代词自动衔接
- 会话 append 留痕，历史可恢复查看

### 4. 版本化存储：V2 的地基
- Project / Document / DocumentVersion / AnalysisRun / ReportVersion 五实体，原文随版本走、永不覆盖
- 迁移分层幂等（版本按 hash+cleaner_version；Run 按 migration_key），中断可恢复
- 18 个历史案例已全量收编，旧评测体系零影响

## 五、实测发现与修复记录（全部来自曦的真实使用）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 多轮对话是假的（追问无上下文） | 会话留痕了但 LLM 每轮只带当前问题 | 历史进 LLM messages + 前端对话流重写 |
| 2 | 「总结一下」被拒绝 | 总结类追问检索零命中 → 材料空 | 零命中回落：历史引用段落 → 全量段落 |
| 3 | 历史编号被大面积判无效 | 回落互斥：历史段回落触发后跳过全量 | 小材料永远全量回落（⊇历史段） |
| 4 | 直接粘贴原始对话无输出 | 清洗器只认 P 编号段落 | v3 自动编号兜底 |
| 5 | 右侧栏突兀、空引用区块刷屏 | 视觉设计 | details 折叠弱化 + 空引用区块隐藏 |

## 七、附录：V1 → V2 概念对照（学习价值）

| 标准 RAG 组件 | 本项目实现 | 特化点 |
|---|---|---|
| 文档切块 | 清洗器分段（P→D 编号） | 段落 = 证据单元，不跨段拼接 |
| 向量索引 | n-gram 关键词索引 | 小材料够用，组件化可替换 |
| 检索召回 | keyword_search + 三层回落 | 词汇鸿沟兜底 |
| 上下文组装 | 材料块 + 多轮历史 | 历史不带旧材料块控 token |
| —— | EVD-01 引用校验 + 完整率 | 标准 RAG 没有的验证闭环 |
