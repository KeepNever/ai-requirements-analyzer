# AI 输出摘录 · case_05_物流二次跟进

> 仅供独立评分用：只含事实层（需求条目/引用/追问），不含 AI 推理理由。

## 一、显性需求条目（指标③评分对象）

- **EN1** 需要一块大屏，挂在指挥中心，由老板点名要求｜引用：P1
- **EN2** 大屏用于前台展示，供参观的合作伙伴观看，体现数据形象｜引用：P2
- **EN3** 大屏具体展示内容未定，需要供应商提供建议｜引用：P3
- **EN4** 需要系统主动发现异常件（破损、丢件、超时）并推送给客服，替代等客户投诉后才知道的被动模式｜引用：P4, P5
- **EN5** 需要将TMS中已有的异常件状态字段推送出来｜引用：P7
- **EN6** 大屏需要展示异常件数据，让老板随时可见管理情况｜引用：P8
- **EN7** 客服部30人都需要预警提醒，最好通过企业微信推送到人｜引用：P9

## 二、追问清单（指标④评分对象）

1. 【缺口】大屏具体展示哪些指标与内容未确定｜【问题】老板对大屏展示内容是否有初步想法？除异常件数据外，是否还需要投诉率、工单量等其他指标？大屏尺寸、分辨率、投放位置（指挥中心还是前台）是否已确定？
2. 【缺口】异常件的判定规则与预警触发条件未明确｜【问题】异常件的判定标准是什么（破损、丢件、超时分别的阈值）？超时是按小时还是按天？预警触发后希望多快推送到客服？是否需要分级预警？
3. 【缺口】TMS异常件状态字段的具体数据结构与更新频率未确认｜【问题】TMS中异常件状态字段的更新是实时的还是批量的？字段结构能否提供样例？接口是推送还是拉取模式？
4. 【缺口】投诉率当前基线数据与目标降幅未量化｜【问题】当前投诉率的具体数值是多少？期望环比降低多少？是否有明确的时间节点要求？
5. 【缺口】预算额度与采购决策流程未明确｜【问题】客服降本专项的预算额度大概范围？采购决策由谁最终拍板？预计什么时间节点需要上线？
