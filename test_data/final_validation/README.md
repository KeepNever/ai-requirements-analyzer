# 正式验证集（final_validation）· 建设与锁定说明

> 状态：**v1.0 已锁定（2026-10-19，曦复核确认）**——正式验证集，一次性盲测专用，锁定后不得作为 Prompt 调优依据
> 身份：正式验证集（M4 冻结基线的盲测用途）。hold_01~03 已转固定回归集，正式验证由本集承担（validation README 口径）

## 建设纪律（曦拍板 2026-10-19）

1. **基线冻结**：Prompt v1.7.1、metrics v1.5、GT v1.1（既有 validation 集）建设期间一律不再改动（git 标签 `m4-freeze`）；
2. **先锁后测**：本集 6 案例 + GT 经曦复核锁定后，才运行最终评测；验证结果只用于评估冻结版本，**不根据结果回改 Prompt**；
3. **盲测纪律**：锁定前不预跑、不给模型看过本集材料；若日后需要继续优化 Prompt，本集转为固定回归集，另建新盲测集；
4. **GT 复核独立性**：GT 依据案例材料证据起草、未反推 Prompt 规则措辞；曦复核时请**先读案例材料、后读 GT**，避免 GT 口径先入为主（尽可能隔离起草过程的影响）。

## 考点覆盖矩阵（相对既有 11 案例的增量）

| 维度 | 既有案例已考 | 本集新增 |
|---|---|---|
| F6 档位纪律 | 贴线（3.45/3.40/1.80）、高频低值、低频高值 | 全案无高档·显式陷阱（FINAL-01/03：痛感真实但无硬节点，诱导跳档）；信号分散重复形态（FINAL-03）；矛盾未决时影响保守计（FINAL-04） |

> 档位事实说明：FINAL-04（最高 3.40）、FINAL-06（最高 3.25）同样无高档需求，但那是**自然结果而非考点设计**——FINAL-04 的考点是矛盾处理、FINAL-06 是稀疏纪律，材料中不存在「诱导跳档」的陷阱结构（FINAL-04 EN1 的 3.40 仅轻微贴线）。仅 FINAL-01/03 将「无高档」写入了 GT 考察点。

## 曦复核清单（锁定流程）

逐案例复核以下五项（建议顺序：先读案例材料 → 再读 GT）：

1. **关键需求集合**：预标注是否认可（尤其 FINAL-03 EN4 不入基准、FINAL-04 EN3 不入基准、FINAL-06 仅 2 条的三处裁量）；
2. **F5**：缺口定级（决定性/关键/普通）与追问设计是否成立；
3. **F6**：维度分与档位（加权值已按 W-v0.1 公式核算，下列区间为各案例全部评分需求的最低至最高加权分：FINAL-01 为 2.40–3.25；FINAL-02 为 1.40–3.60；FINAL-03 为 2.40–3.40；FINAL-04 为 2.60–3.40；FINAL-05 为 2.40–3.90；FINAL-06 为 2.40–3.25）；
4. **F7**：三档判定与依据（重点：FINAL-02 EN3 待确认 vs 不支持的区分、FINAL-04 全线待确认、FINAL-05 三档对照）；
5. **引用证据**：F3 引用与材料 P 编号逐一核对，不得有证据不一致（validation 集 5 处修复的教训）。

复核通过后：GT 状态行改 v1.0 已锁定（注明日期），接入评测管线（run_eval 扩展 final dataset 路由，另行提交），一次性盲测。

## 同源偏见声明

本集仍由析起草，同源偏见风险与 validation 集相同（validation README §同源偏见声明）。缓解措施：① 曦先读材料后读 GT 的复核顺序；② 复核重点放在「裁量项」（关键集合边界、影响分定级、F7 三档判定）；③ 备选升级（曦独立重写 1~2 个案例 GT、或引入第二起草人）继续保留，视本轮验证结果再议。
