# CASE-05 迅达物流 · 二次跟进会

> 材料形态：二次跟进会转写｜行业：物流运输｜虚构数据｜⚠ 本案例为「信号强度陷阱」设计

## 背景

迅达物流是一家区域快运企业，自有 TMS 系统为自研。本次为数析云与客户 IT 部、客服部的二次跟进会。

## 原始材料

P1 【王经理-IT】上次聊完，老板特意交代要一块大屏，挂在指挥中心，这个是老板点名要的。

P2 【赵主管-客服】对，老板的想法是平时来参观的合作伙伴多，前台有块数据大屏有面子。

P3 【王经理】大屏上具体放什么内容，老板没细说，让你们给建议。

P4 【赵主管】我补一个实际的问题：异常件——就是破损、丢件、超时的——现在要等客户投诉了客服才知道。月均投诉三百多单，处理得非常被动。

P5 【赵主管】理想状态是：系统发现异常件就主动推给我们，客服主动联系客户，别等人家来投诉。

P6 【王经理】对，投诉率这个指标老板也天天念，是挂在客服部的 KPI。

P7 【赵主管】技术上我们的 TMS 里本身有异常件的状态字段，问题是怎么把它推出来。

P8 【王经理】大屏能不能也放异常件数据？这样老板随时看得见我们在管这事。

P9 【赵主管】客服部 30 个人都要用预警提醒，最好走企业微信推到人。

P10 【王经理】提醒一下，大屏这个事老板很执着。上次一家供应商的方案里没大屏，方案直接被否了。

P11 【王经理】不过说实话，那大屏天天也就是领导来参观了开一开，平时都黑着。

P12 【赵主管】我们真正要的成绩是投诉率环比降下来，这才是能写进年终总结的东西。

P13 【王经理】TMS 是我们自研的，接口文档齐全，人也在，对接不难。

P14 【王经理】预算走今年的客服降本专项，额度是够的，这块不用担心。
