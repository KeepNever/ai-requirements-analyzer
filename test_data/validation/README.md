## 同源偏见声明（诚实边界）

本验证集由析（AI）起草，而析同时是 Prompt 的作者与历轮评测的执行者——存在**同源偏见**：GT 的口径可能与 Prompt 的规则写法天然一致，导致验证分数虚高。因此：

1. **全部 6 份 GT 必须经曦人工复核、逐条拍板后才算锁定**；曦的修改本身是对偏见的第一次校正；
2. hold_01~03 锁定后冻结，任何 Prompt 迭代前不得预跑；
3. 更强的去偏见手段（如曦独立重写 1~2 个案例的 GT、或引入第二起草人）列为可选升级，M4 再议。

## 锁定流程

1. 曦复核 6 份 GT：重点看 F5 级别标注、F6 加权计算与档位、F7 结论、关键需求集合；
2. 有修改直接改文件并把状态行改为 v1.0（已锁定），注明日期；
3. 锁定后由析接入评测管线（需扩展 run_eval 支持 validation 目录与独立口径），先跑开发集新增 3 案例，hold_01~03 留到 M3 收口时一次性跑；
4. 验证结果写入评测报告时必须标注「验证口径」，与开发口径分开陈述（07 v1.1 锁定规则）。
