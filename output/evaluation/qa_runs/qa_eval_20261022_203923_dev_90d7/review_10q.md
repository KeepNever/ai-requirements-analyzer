## 三、conflicting 题（DEV-CONF-017）失败归因

**现象**：拒答判断失分（系统 sufficient=true，GT 期望识别冲突），召回 0.5。

**逐层归因**：

| 层 | 结论 | 证据 |
|---|---|---|
| 检索 | **未召回 D006**（孙经理「费用表全公司都要用」）——query「受众范围」与 D006 字面零重叠 | hits 只有 D002(无关)+D007 |
| 生成 | **无错**——模型只看到 D007 一方证据，回答正确支撑了它看到的唯一信息 | 原始输出只基于 D007 |
| 材料 | **弱支撑**——D006 的核心是费用表使用范围，与「看板受众」的冲突是间接的；题干弱冲突定性成立 | 原文对照 |

**结论**：conflicting 失败主因 = **检索层词汇鸿沟（D006 未召回）+ 材料本身弱冲突支撑不足**，不是「模型不会识别矛盾」——模型根本没看到冲突的另一面。这修正了一个直觉：不需要立即改 Prompt 加矛盾识别，先要解决的是「冲突双方的证据都进入材料块」。

## 四、复核结论（供下一轮决策）

1. **答案质量整体可靠**：10 题无一编造、无一引用错位，答案完整率 90%——V2 问答的「证据优先」设计在人工复核下成立；
2. **唯一系统性缺口在检索层**：词汇鸿沟导致的关键段漏召回（本例 D006），与基线自动指标（召回 0.889）互相印证。候选优化（下轮拍板）：a) 检索 query 扩展/同义映射；b) 小材料全量回落阈值放宽（当前 ≤40 段已兜底大部分）；c) 语义向量检索组件——按组件化设计可替换；
3. **conflicting 的正确路径**：先补「含真实双源冲突」的测试材料（现有案例不足，不硬造），新材料先入 DEV 调试，LOCKED 只做回归确认——维持四审纪律；
4. **Word 导出**维持第三优先级不变。
