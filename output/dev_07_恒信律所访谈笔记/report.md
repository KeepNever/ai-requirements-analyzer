## F1 客户背景

- 律所规模 45 名执业律师，分 6 个团队（D001）
- 行政与 IT 均无专职人员，由行政主管林姐兼管系统事务（D001）
- 律师办案进度散落在各自电脑的文件夹和 Excel 里，合伙人想看全所案件状态要挨个微信问团队长（D002）
- 案件管理用的是所里十年前找外包做的小系统，B/S 架构，数据库 SQL Server，没有现成接口，外包公司已经联系不上了（D004）
- 所里今年信息化预算 8 万，超过 10 万要重新开合伙人会（D009）

## F2 业务目标

- 让合伙人能直接看到全所案件状态，不必挨个微信问团队长（D002）
- 在每周一下午合伙人会议前拿到各团队在手案件数、本月创收、回款情况（D003）
- 减少行政每月出账单和律师工时统计的手工核对工作量与差错（D005）
- 在保证案件数据不出所内的前提下实现数据查询与统计（D008）

## F5 待确认信息（缺口 → 影响 → 追问）

| 缺口 | 级别 | 影响 | 追问 |
|---|---|---|---|
| 老系统（SQL Server）的数据结构、数据量、是否可开放只读数据库访问或导出权限未知 | **决定性** | 决定项目是否可行、采用何种集成方式（直连数据库/定时导出/中间库），直接影响报价与交付周期 | 能否协调所里拿到老系统数据库的只读访问权限或定期导出机制？老系统表结构文档是否还在？数据量大概多少？ |
| 客户是否接受私有化部署（客户内网/指定服务器），以及所内是否有可用的服务器与运维条件 | **决定性** | 决定部署形态与整体方案可行性，影响报价（私有化通常成本更高）与交付方式 | 所里是否有可用的内网服务器或指定服务器资源？是否接受私有化部署？后续系统日常维护由谁负责（林姐兼管是否可行）？ |
| 预算上限与私有化部署成本的匹配情况：预算 8 万、超 10 万需重开合伙人会 | **关键** | 影响报价策略与方案范围裁剪，可能决定是否需要分期实施或缩减功能 | 8 万预算是否包含私有化部署与老系统对接的全部费用？若方案接近或超过 10 万，合伙人会重新决策的周期大概多久？ |
| 自然语言查询与交叉组合查询所涉及的数据表关联复杂度（是否涉及多表关联） | **关键** | 决定自然语言查询能力能否覆盖客户实际问法，可能需要改用自助报表或定制方式实现 | 「按客户、按案件类型、按月份组合着查」具体是几个维度的组合？是否涉及跨多张业务表的关联统计？能否举 2-3 个真实查询例子？ |
| 看板指标（在手案件数、本月创收、回款）的数据来源与口径定义 | **关键** | 影响看板实现方式与数据准确性保障，可能需要额外的数据归集工作 | 「在手案件数」「本月创收」「回款」分别以什么数据为准？是取自老系统还是需要律师另行填报？口径由谁定义？ |
| 账单与工时统计的输出格式与客户交付方式 | **普通** | 影响报表模板设计与交付体验，不影响方案成立 | 账单和工时统计是否有固定模板或格式要求？是导出 Excel/PDF 还是需要直接发送给客户？ |

## F7 能力匹配

| 对象 | 结论 | 依据 |
|---|---|---|
| EN1 看板：每个团队在手案件数、本月创收、回款情况 | 匹配 | C2 实时看板支持核心指标实时刷新并支持大屏投放，可覆盖看板呈现需求；数据来源依赖老系统集成（D004），属实施工作，按规则不因此降档，实施风险与工作量写入此处 |
| EN2 每月给客户出账单和律师工时统计 | 匹配 | C1 自助报表支持拖拽式报表搭建与 30+ 图表类型，可覆盖账单与工时统计报表的生成；若涉及复杂计算字段（如工时汇总规则）需定制，属实施细节 |
| EN3 自然语言查询（如「上个月张律师团队的回款是多少」） | 部分匹配 | C3 自然语言查询支持自然语言转 SQL 及常用聚合，可覆盖「上个月张律师团队回款」这类常用聚合查询；但 C3 明文不支持复杂多表关联查询，若实际查询涉及多表关联则存在缺口 |
| EN4 交叉组合查询（按客户、案件类型、月份组合） | 待确认 | C3 不支持复杂多表关联查询，而交叉组合查询是否构成多表关联取决于实际数据模型与查询维度组合，缺少客户真实查询样例与数据表结构证据，无法判断是否被覆盖 |
| EN5 查数必须准确 | 匹配 | 数据准确性属质量属性，C1/C2/C3 均以数据查询与呈现为核心能力，准确性由数据源与集成质量保障，属实施与数据治理范畴，能力清单层面无排除项 |
| EN6 案件数据绝对不能出所内 | 匹配 | C7 部署方式支持私有化部署（客户内网/指定服务器），可满足数据不出所内的要求；信创/国产化环境需评估确认，当前材料未提及信创要求 |
| IN1 老系统（SQL Server）数据集成 | 匹配 | C5 数据集成提供 50+ 标准连接器（含主流数据库），SQL Server 属主流数据库范畴可覆盖；老系统无现成接口（D004）属实施对接工作，按规则保持匹配，实施风险与工作量写入此处 |
