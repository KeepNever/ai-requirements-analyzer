## F1 客户背景

- 律所规模45名执业律师，分6个团队（D001）
- 行政与IT均无专职人员，由行政主管林姐兼管系统事务（D001）
- 律师办案进度散落在各自电脑的文件夹和Excel里，合伙人想看全所案件状态要挨个微信问团队长（D002）
- 案件管理用的是所里十年前找外包做的小系统，B/S架构，数据库SQL Server，没有现成接口，外包公司已经联系不上了（D004）
- 数据安全要求：案件数据绝对不能出所内，合伙人会上讨论过云端方案被否了，客户都签了保密协议（D008）
- 今年信息化预算8万，超过10万要重新开合伙人会（D009）

## F2 业务目标

- 让合伙人能直接查看全所案件状态，不再依赖挨个微信询问团队长（D002）
- 在每周一下午合伙人会议前提供各团队在手案件数、本月创收、回款情况（D003）
- 提升行政侧账单与工时统计效率，减少手工核对与错误（D005）
- 保证对外数据准确，维护律所专业形象（D007）
- 在数据不出所内的前提下实现信息化（D008）

## F7 能力匹配

| 对象 | 结论 | 依据 |
|---|---|---|
| EN1 团队经营看板（在手案件数/本月创收/回款） | 匹配 | C2 实时看板支持核心指标实时刷新并支持大屏投放，可覆盖看板展示需求；但数据源来自 D004 所述无接口的老系统，需通过 C5 数据集成或定制对接完成数据接入，实施工作量写入方案，不构成降档 |
| EN2 客户账单与律师工时统计报表 | 匹配 | C1 自助报表支持拖拽式搭建与 30+ 图表类型，可覆盖账单与工时统计报表；若涉及复杂计费计算字段，C1 说明复杂计算字段需定制，属实施范围，结论保持匹配 |
| EN3 自然语言查询（如「上个月张律师团队的回款是多少」） | 部分匹配 | C3 自然语言查询支持常用聚合，可覆盖单维度聚合类问法；但 C3 明确不支持复杂多表关联查询，若客户问法涉及跨表关联则需定制开发，存在能力缺口 |
| EN4 按客户/案件类型/月份组合交叉查询 | 部分匹配 | C1 自助报表支持拖拽式多维分析，可覆盖组合交叉查询；但若组合维度涉及多表关联的复杂计算，C1 说明复杂计算字段需定制，存在定制范围 |
| EN5 查询数据准确性 | 匹配 | 数据准确性属报表与看板的基础质量属性，C1/C2 能力本身以数据展示为核心，准确性由数据集成与口径定义保障，能力清单未排除，判定匹配 |
| EN6 案件数据不出所内（本地化部署） | 待确认 | 能力清单 C1~C6 均未说明部署方式（是否支持本地/私有化部署），缺少清单级证据判断能否满足数据不出所内的硬性要求，需确认产品部署形态 |
| IN1 老系统（SQL Server）数据接入 | 部分匹配 | C5 数据集成提供 50+ 标准连接器，SQL Server 属主流数据库可覆盖；但 D004 显示老系统无现成接口且外包失联，若为标准库表可直连则匹配，若需私有协议对接则 C5 说明需定制开发，存在定制范围 |
