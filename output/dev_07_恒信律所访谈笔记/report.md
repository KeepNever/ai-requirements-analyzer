## F1 客户背景

- 律所规模 45 名执业律师，分 6 个团队（D001）
- 行政与 IT 均无专职人员，由行政主管林姐兼管系统事务（D001）
- 律师办案进度散落在各自电脑的文件夹和 Excel 里，合伙人想看全所案件状态要挨个微信问团队长（D002）
- 案件管理用的是所里十年前找外包做的小系统，B/S 架构，数据库 SQL Server，没有现成接口，外包公司已经联系不上了（D004）
- 数据安全要求：案件数据绝对不能出所内，合伙人会上讨论过云端方案被否了，客户都签了保密协议的（D008）
- 预算：所里今年信息化预算 8 万，超过 10 万要重新开合伙人会（D009）

## F2 业务目标

- 让合伙人能掌握全所案件状态，不必挨个微信问团队长（D002）
- 支撑每周一下午合伙人会议前的数据查看需求（D003）
- 提升行政出账单与工时统计的效率与准确性，减少手工核对与退回重做（D005）
- 保证给客户看的数据准确，维护律所专业形象（D007）

## F7 能力匹配

| 对象 | 结论 | 依据 |
|---|---|---|
| EN1 看板（在手案件数、本月创收、回款） | 部分匹配 | C2 实时看板支持核心指标实时刷新与大屏投放，可覆盖看板展示；但数据来源依赖老系统 SQL Server 集成（C5 标准连接器可覆盖 SQL Server），而指标口径与数据可得性待确认，故为部分匹配 |
| EN2 每周一会议前可用 | 匹配 | C2 实时看板延迟 < 1 分钟，可满足每周固定时点查看的时效要求 |
| EN3 每月账单与工时统计 | 部分匹配 | C1 自助报表支持拖拽搭建与 30+ 图表，可承载账单与工时统计报表；但复杂计算字段需定制，账单口径若涉及复杂计算需定制开发 |
| EN4 大白话问数 | 部分匹配 | C3 自然语言查询支持自然语言转 SQL 与常用聚合，可覆盖「上个月张律师团队的回款是多少」类查询；但不支持复杂多表关联查询，需确认该问数是否涉及多表关联 |
| EN5 交叉查询（按客户/案件类型/月份组合） | 待确认 | C3 明确不支持复杂多表关联查询，而按客户、案件类型、月份组合查询是否构成多表关联取决于老系统数据结构，材料未说明，证据不足无法判定 |
| EN6 查数必须准确 | 待确认 | 能力清单未提供数据准确性/校验相关能力条目，无法对照判定 |
| EN7 案件数据不能出所内 | 待确认 | 能力清单未说明部署形态（公有云/私有化），无法判定是否满足数据不出所内的要求 |
| IN1 老系统 SQL Server 数据集成 | 部分匹配 | C5 数据集成含 50+ 标准连接器覆盖主流数据库，SQL Server 属标准连接器范围；但老系统无现成接口、外包失联，实际可接入性待确认 |
| IN2 私有化/本地化部署 | 待确认 | 能力清单未包含部署形态说明，无法判定是否支持本地化部署 |
