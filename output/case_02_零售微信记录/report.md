## F1 客户背景

- 客户为连锁门店企业，拥有80家门店（D001）
- 门店日报目前由店长每晚手工填写Excel发到群里（D001）
- 会员和销售数据存放在名为「店务通」的收银SaaS系统中，该SaaS在行业内使用较多（D008）
- 周总监为业务负责人，日常需人工爬楼查看各店日报（D001）

## F2 业务目标

- 实现各门店销售数据自动汇总，替代人工手填Excel（D001、D002）
- 让管理者无需开电脑即可在手机上查看门店经营数据（D003）
- 通过各店对比排行快速识别业绩落后门店（D005）
- 提升提成核算效率与准确性，减少月底对账耗时（D009、D011）

## F7 能力匹配

| 对象 | 结论 | 依据 |
|---|---|---|
| EN1 每天早上9点前自动生成昨日各店销售额、客单价、会员新增日报 | 部分匹配 | C1自助报表支持拖拽搭建与多图表，C2实时看板支持核心指标刷新，可承载日报展示；但日报需从「店务通」SaaS自动取数，C5数据集成仅覆盖50+标准连接器，私有协议需定制开发，「店务通」是否在标准连接器内未知，自动汇总取数环节存在定制可能，故为部分匹配 |
| EN2 日报支持手机端查看 | 匹配 | C6移动端明确支持iOS/Android查看报表与预警，与需求核心功能一致 |
| EN3 各店对比排行 | 匹配 | C1自助报表支持30+图表类型，可搭建门店对比排行视图；C2实时看板支持核心指标展示 |
| EN4 查看导购销售提成数据 | 部分匹配 | C1自助报表支持拖拽搭建，但提成计算涉及按比例规则的计算字段，C1说明「复杂计算字段需定制」；若提成规则仅为简单比例，标准计算字段或可覆盖，若含特殊情形则需定制，故为部分匹配 |
| EN5 提成数据必须准确 | 部分匹配 | 数据准确性依赖提成计算逻辑的完整实现，C1复杂计算字段需定制，准确性保障取决于定制开发质量，故为部分匹配 |
| EN6 月度费用对比表 | 待确认 | C1自助报表可搭建对比表，但费用数据来源系统未知（财务系统或店务通），C5数据集成能否覆盖该数据源缺少证据，无法判断核心功能是否被覆盖 |
| EN7 预算一年一万以内 | 待确认 | 能力清单未包含定价信息，无法判断产品报价是否落在该预算范围内 |
| EN8 月底前挑两个店试点 | 待确认 | 试点可行性取决于「店务通」数据接入方式与定制工作量，当前缺少数据源对接证据，无法判断能否在月底前完成试点部署 |
